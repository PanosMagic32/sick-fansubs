# internal/push — Agent Navigation

Web push delivery: the fan-out sender that transports committed `user_notifications` events to the recipient's subscribed devices.

## Open this file when

- changing the fan-out mechanics (concurrency cap, retries, TTL, topic, dead-endpoint cleanup), the payload shape, the VAPID claims/keys, or the `Notifier`/`TestSender` seams the handlers consume.

## Folder-local conventions

- **Push is a channel, not a pipeline.** The in-app feed row is the durable source of truth; `NotifyPush` fires AFTER the emitting transaction committed (the handlers hand the store's `NotificationEvent` over post-commit). Fan-out failure loses nothing — at-most-once best effort by design.
- **Suspension:** `deliver` re-checks the recipient's `status = 'active'` before any preference or subscription read. Suspension suppresses delivery but RETAINS the subscription and preference rows, so a reactivation resumes delivery — both pinned by `TestDeliverSkipsSuspendedRecipient`.
- `Notifier` is the handler seam (the `mail.Sender` pattern): nil = disabled (dev without the VAPID secret, and tests). `Sender` satisfies it. `TestSender` is the SECOND seam — the self-test send the account page's settings button calls: nil = disabled, and the handler reports `delivered: 0` instead of failing.
- `deliver` runs under a FRESH bounded context (`deliverTimeout`) — a cancelled request must never cancel the delivery that follows its own commit; the request context travels in as `logCtx` for request-ID correlation ONLY, and every line is written through `logging.From(logCtx)`.
- **Log discipline:** log lines carry the subscription id (field key `subscriptionId`), the push-service FAMILY (`service`), and the status/class — never the endpoint, never usernames. Network errors are logged by CLASS (`pushErrorClass`: timeout | network) because webpush-go's errors embed the endpoint URL. The dead-endpoint delete uses its own short timeout (5 s) so cleanup never outlives the fan-out window.
- Error classes: 404/410 → delete the row (dead subscription); 429/500/502/503/504 → retry (2 retries, 1 s/2 s backoff, bounded by `deliverTimeout`); other 4xx → log and drop. TTL = 86400 s for the reaction, follow, and `comment_removed` kinds; `new_content` carries its own 604800 (see the per-kind bullet below). `Topic` = the content id (collapses a burst on one content, Android). A `test` send carries no topic (nothing to collapse on — the header is simply absent). **Test seam:** the backoff ladder lives on `Sender.backoff` (default 1 s/2 s in `NewSender` — pinned by `TestDefaultBackoffLadder` without sleeping); the retry tests inject a zero backoff so they pin the retry COUNT, not real sleeps.
- **Record size = request body size (the Firefox-for-Android failure class).** `webpush-go` PADS the single aes128gcm record up to `Options.RecordSize`, whose default is `MaxRecordSize` (4096): leaving it unset pads every POST body to exactly 4096 bytes whatever the payload. Mozilla autopush refuses more than 4028 characters (413 / errno 104) and documents ~2744 for BRIDGED (GCM/FCM/APNs) connections, so every bridged subscription is refused while direct endpoints (desktop Firefox, Chrome, Apple) keep working. `sendOne` sets `RecordSize: recordSizeFor(len(body))` = `max(minRecordSize 1024, payload+recordOverhead 256)`; the floor keeps length-hiding padding, the overhead clears `payloadFraming` (86 + 1 + 16), and `maxBridgedRecordSize` (2688) is the ceiling the worst realistic payload stays under. Do NOT set the option back to zero, and never raise the composed size past the bridged ceiling — `TestRecordSizeFor` + `TestDeliverSendsWithHeaders` (the body equals the composed size) are the pins.
- **Per-endpoint report.** `sendOne` returns `DeliveryOutcome{SubscriptionID, Service, Accepted, Status, Removed}`; `SendTest` returns `TestReport{Delivered, Endpoints}` with one outcome per row in the STORE's order (`created_at_ms, id` — pinned by `TestSendTestReportOrder`), written by index so no mutex is needed. `Service` is `pushServiceFamily(endpoint)`: a CLOSED, COARSE vocabulary (`mozilla` | `fcm` | `apple` | `other`). The key material and the endpoint's URL, path, and token NEVER leave the sender; of the endpoint's detail, only the coarse `service` family reaches a log line or the report (the settings list returns the endpoint to its own owner — `push_store.go`). This exists because `delivered` alone is a union count — it can let a healthy desktop mask a refused phone.
- **Outbound redirects are refused.** The send client's `CheckRedirect` returns `http.ErrUseLastResponse`, so the client hands back the 3xx instead of following it: a user-supplied endpoint cannot aim the POST at a second host. The 3xx is logged and dropped by the default arm (no retry). Pinned by `TestSendOneRefusesRedirects`. **Accepted residual:** the first hop itself is only https-shape checked (`internal/handler/push.go`); a private/loopback host is not refused — host-class checks lose to DNS rebinding — so TLS system-root verification is what bounds it (an internal service cannot present a public-CA certificate for the attacker's hostname), and the VAPID JWT minted for the endpoint is audience-bound to it, so it cannot be replayed at a real push service.
- **Payload title budget.** `payloadFor` returns the marshalled body, the bytes an over-budget title lost, and an error. A title that would push the composed record past `maxBridgedRecordSize` is cut to the LONGEST rune prefix that fits (binary search across marshals) because a legacy-imported title is the one unbounded field; the fan-out logs `push payload title trimmed` with the kind and `titleBytesDropped` (never the title). The self-test payload can never need the trim.
- **The optional-kind gate is PER KIND.** `deliver` asks `store.EffectivePushEnabled` with a default that is moderator+ ON for the audience kinds and OFF for `draft_activity` at every role — the staff notice is opt-in by ruling, and its recipients always carry an explicit row (the emitter requires one), so the OFF arm is the guarded fallback after a row vanishes. Pinned by `TestDeliverDraftActivityDefaultsOff`, which shows the same moderator account still receiving a heart.
- **Draft-notice TTL.** `draft_activity` rides the 24 h default (`ttlSeconds`) — the notice's value decays like a reaction's; the durable copy is the in-app row.
- The payload JSON keys ARE the service worker's contract (`contentId`, not `contentID`) — pinned by `TestPayloadJSONKeys`. `commentId` is `omitempty`: present for the comment kinds (including `comment_removed`, whose tag uses it), ABSENT for `content_updated` and `new_content` (the worker's deep-link logic keys off its absence — pinned by `TestPayloadOmitsEmptyCommentID`, which marshals both content kinds). `draftAction` is `omitempty` the same way: present ONLY for `draft_activity` (its three-action vocabulary picks the worker's verb, and an action the worker does not know raises NO notification rather than a wordless one) and pinned by `TestPayloadDraftAction`. Change a key = change the worker's reader in the same commit. **`comment_removed` is the ACTORLESS kind**: the handler leaves `ActorUsername` empty, and sw.js's `sentenceFor` runs its branch BEFORE the actor guard (a missing actor would otherwise drop the whole notification) and its `deepLinkPath` skips the `#comment-` fragment (the comment is gone).
- **Self-test send:** `SendTest` delivers one message of kind `test` to the caller's OWN subscriptions and reports `TestReport{Delivered, Endpoints}` — how many endpoints ACCEPTED it (200/201) plus the per-endpoint outcomes (see the per-endpoint report bullet above). It is SYNCHRONOUS — the user is waiting on the request — so it runs under its own `testDeliverTimeout` (20 s, BELOW the server's 30 s write deadline; the fan-out's 60 s would outlive the response) and honours the caller's context. The per-kind preference gate is deliberately ABSENT (the user asked for the message), there is no feed row, and `Event.RecipientID` must be set: the dead-endpoint cleanup scopes its delete to it. `testKind` is NOT a feed kind — it never enters `user_notifications` or `notification_preferences`, and the payload body carries empty content fields (no `commentId` key) — pinned by `TestPayloadTestKindBody`. The worker renders it from its own template and links to `/account`; changing that contract means changing `sw.js` in the same commit.
- **Per-kind TTL:** `ttlSeconds(kind)` is the TTL-header switch — `new_content` = 604800 s (7 days, `newContentTTLSeconds`), every other kind = the 86400 default (pinned by `TestTTLSeconds` + `TestDeliverSendsNewContentTTL`). New kinds add their own TTL numbers.
- `webpush-go` always emits the single `vapid` Authorization scheme and derives the JWT `aud` from each endpoint's origin — no per-browser branching exists or is needed.
