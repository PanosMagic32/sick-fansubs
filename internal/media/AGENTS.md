# internal/media — Agent Navigation

Target media storage layout + the pure-Go processing pipeline. The single source of truth for where a processed image lives and how a source image becomes the served file.

## Open this file when

- changing the storage layout, the processing pipeline (decode/resize/encode), the size/dimension limits, or the output formats.

## Folder-local conventions

- `RelativePath`/`ImagePath` (and the unexported directory join) are the only path builders; `ServedPath` is the ONLY storage→served mapping (drops the 2-hex subdirectory) — serving (internal/handler) and migration (internal/migration) must build paths here, never inline. The stored-reference grammar (`ParseStorageReference`, the write gate and the sweep's shared rule) requires the 2-hex subdirectory to equal `id[:2]`, so a reference the gate accepts can never address a different file than the layout resolves. A value written before this rule landed is not rewritten — check the stored references before cutover; the next write of such a row is refused.
- `ProcessContentThumbnail` implements the pipeline end to end: bounded input (`MaxInputBytes`, exported — callers that read the source first must enforce the same bound) → DecodeConfig pre-check (≤8192px per axis AND ≤2^24 total pixels — the total-pixel bound is the decompression-bomb guard, sentinel `ErrPixelsTooBig`) → decode → EXIF dropped by re-encode → proportional 1280×720 fit → JPEG quality 85 / PNG on transparency → atomic write. Content thumbnails only.
- `ProcessAvatar` is the user-avatar pipeline: the SAME bounded input + header checks (both processors share `decodeBounded` — never diverge them), then the largest CENTERED square crop (`centerSquareCrop` — draw.Src preserves alpha), scale to EXACTLY 200×200 up or down (`scaleTo`, `avatarSize` — small sources are upscaled), always PNG. The two processors share the bounds and the write path but differ in geometry/format — do not merge them into one function with flags.
- `Sweep` (sweep.go): candidates must match the STORED grammar exactly (`<2hex>/<32hex>.(jpg|png)` with the subdirectory equal to `id[:2]` — `ParseStorageReference` plus the subdir check); non-conforming files are NEVER touched. Referenced files are kept regardless of age; unreferenced files older than the grace window are removed; stale `.processing-*` leftovers older than the window are removed too. The layout depth is the exact rule for both: only entries one subdirectory below the images root are ever considered — image candidates additionally require that directory to equal `id[:2]` — temp leftovers included. `SweepGrace` (24 h) is the fixed constant — the same fixed-constant policy as `MaxInputBytes`. The walk checks its `context.Context` between entries and returns the cancellation error, so shutdown never waits on an unbounded scan. Every orphan removal is logged by asset id — never the storage path (logging.md rule 8) — and a temp leftover by its basename; per-file failures are counted, not fatal.
- Upload and content identifiers come from `internal/id` (`id.New` — fresh random 32-hex); the content-derived `MediaIDForBytes` (migration) belongs to the one-time import, never the runtime. The rules are in [`docs/patterns/go/ids.md`](../../docs/patterns/go/ids.md).
- The backup/restore half (backup.go): `ManifestPathFor` is the single discovery rule; `ReadMediaManifest` refuses an over-bound sidecar explicitly (the size check is `maxManifestBytes`, not silent truncation) and `ValidateManifest` checks the field contract (both filenames clean single-component names, 64 lowercase-hex SHA, positive timestamp); `VerifyMediaTar` enforces the plain-filename rule too — a hostile sidecar must never steer extraction outside its unit directory. `cmd/restore` calls both BEFORE the staged restore; `ExtractMediaTar` runs after database activation via the database package's `PostActivation` hook. The extraction caps (`maxExtractFileBytes`/`maxExtractTotalBytes`) bound a tampered tar's disk usage, not production media sizing — revisit only with measured need.
- The media tree is trusted-local. Only the pipeline and the import write files there, both through `writeAtomic` with validated names, and tar build/extraction refuse non-regular entries — a symlink appears only with filesystem write access to the data directory, which is already full compromise. `writeAtomic` leaves 0600 and a restore's extraction writes 0644; the app is the only reader (Caddy proxies to it) and runs as the writing uid, so the mode difference is not observable.
- WebP is decode-only, decoded by explicit call (`webp.DecodeConfig`/`webp.Decode` behind the RIFF/WEBP signature check in `process.go` — the package is imported for its API, never blank); output is never WebP (pure-Go encoder constraint).
- The sentinel errors (`ErrInputTooLarge`, `ErrDimensionsTooBig`, …) live in `errors.go` (the package vocabulary, docs/patterns/go/errors.md) and are the report-code mapping surface for `cmd/importmedia` and the upload handler — keep messages out of that mapping. The processors wrap a sentinel and FLATTEN the cause (`%w: %v`): the sentinel is the contract, the third-party decoder error is not. A source-read failure is the one unsentineled arm — it is infrastructure, the upload boundary answers its masked 500, and the reader's error type is not part of the contract.
