# internal/search — Agent Navigation

Pure text-processing rules for search: Greek accent normalization, FTS5 query construction, and the Greek title-sort collation. No database or HTTP dependencies — the import tool, the rebuild command, the handler, and the store all share this ONE implementation.

## Open this file when

- changing Greek accent normalization, FTS5 query construction, token-safety rules, the no-token error, or the title-sort collation (`collate.go`).

## Folder-local conventions

- **Normalization symmetry is the correctness property:** indexed text and query text must flow through the same `normalize` — that shared path is what makes accent-insensitive Greek search work. Never add a second normalization copy at a caller. (The STAFF list filter is the one surface that does not go through the index at all — see `FilterTokens` below.)
- `normalize` strips precomposed Greek accents (tonos/dialytika forms) and combining marks; case is preserved because the tokenizer's own case folding handles it (proven for Greek). `unicode61 remove_diacritics` alone is NOT sufficient — it misses precomposed Greek letters, so the Go-side map is the real mechanism. Precomposed Latin text passes through untouched; a combining mark is stripped whatever script it belongs to. Modern monotonic Greek forms are the map's coverage — polytonic (Greek Extended) forms are not folded (recorded acceptance).
- `Text(parts...)` joins non-empty parts with single spaces and normalizes — one indexed-text builder for blog posts (title, subtitle, description) and projects (title, description).
- `BuildQuery` turns raw user input into a safe bound SQL parameter: FTS5 specials become SPACES (never deleted — deleting would concatenate neighboring words), reserved words (`and`/`or`/`not`/`near`) are dropped case-insensitively as whole words, every token that leaves no letter or number after normalization is dropped too, and every surviving token is phrase-quoted; only the LAST token gets a `*` prefix, only when it has ≥ 2 runes. A query with no surviving token is `ErrNoTokens`. The result is never interpolated into SQL.
- `ErrNoTokens` lives in `errors.go` (the package vocabulary, docs/patterns/go/errors.md) and maps to a 422 violation `{field: q, code: invalidFormat}` at the handler — the mapping stays at the caller, not in this package.
- **Collation:** `collate.go` owns the Greek title-sort rule — `CollationGreek` (`sf_greek`), `SortKeyRuneLimit` (200 runes), `Compare` (the driver callback), and `SortKey` (the cursor key). The invariant that makes a keyset cursor sound: folding never changes a comparison, i.e. `Compare(SortKey(a), SortKey(b)) == Compare(a, b)` — pinned by `TestSortKey_FoldingInvariance`. The key's byte order is NOT the sort order (Greek letters sort before Latin/digits), so a key is only comparable through `Compare` — never `strings.Compare`.
- **`Fold` + `FunctionFold`:** `Fold` is the collation's per-rune folding applied to a WHOLE string (no `SortKey` truncation) — accents and combining marks stripped, lowercased, final sigma folded. It backs the `sf_fold` SQL function (`FunctionFold`, registered by `internal/database`, canary `TestFoldFunction_RegisteredBeforeOpen`) and the staff content filter's needle, so SQL and Go fold a title identically. Below the rune bound `Fold(s) == SortKey(s)`; a caller that needs one of the two must use the one whose contract it needs (a key is comparable only through `Compare`; a needle is only for substring matching).
- **`FilterTokens`:** the staff filter's query split. It cuts the query at every character that is neither a letter nor a digit, folds each piece, and returns them in order — the store ANDs one `instr(sf_fold(title), ?) > 0` per token, which is what makes `dr stone` find `Dr. Stone` and matches where the public search's FTS5 query is cut (`BuildQuery` + the `unicode61` tokenizer treat punctuation the same way). The rules are not identical: `BuildQuery` also drops reserved words and prefix-matches the last token, a needle here is a plain substring, and a query with no letters and no digits is NO filter (the public search 422s the same input) — the two rules deliberately differ, and one rune class diverges explicitly: FTS5 counts every letter and number category as a token, the split keeps decimal digits only (a numeral like `Ⅷ` is a word there and a separator here). Keep the split here, not in a caller: it is the word boundary the two search surfaces share.
- Keep this package dependency-free (no database, no HTTP) — the shared-normalization design depends on every caller importing it. The reverse edge is fine: `internal/database` imports this package to register the collation.
