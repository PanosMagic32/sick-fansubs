# web/src/shared — Agent Navigation

Cross-cutting frontend code: the API client and wire types (`api/`), the Greek message catalog (`catalog/`), icons, and the shared UI vocabulary (control classes, form sheet, the `formField` directive), plus the pure helpers in `utils/`, the PWA install affordances in `pwa/`, public config in `config/`, and the cross-feature event contracts in `events.ts`.

## Open this file when

- changing API client behavior, wire DTO types, or catalog copy.
- adding or modifying a shared UI primitive.

## Placement

- `api/` is the feature-free HTTP transport (request, problem parsing, CSRF state, 401 callback, error classes, the client timeout). Endpoint functions and their DTOs live in each feature's `data-access/` — never here. `request-signal.ts` holds the shared client-timeout composition (`API_REQUEST_TIMEOUT_MS` + `requestSignal`); `requestForm` is the multipart variant, used by the media upload and the avatar upload — it shares `doFetch`/`handleResponse` with `request`, so problem parsing and the 401 transition can never drift.
- `ui/` holds UI primitives: `loading-spinner`, `error-banner`; the avatar chip (`avatar.ts` + `avatar.css` — the image → initial → empty-circle fallback chain); `pager-nav` (the URL-carried cursor paging bar: Previous / page-size select / Next with the «Σελίδα X από Y» caption BELOW it, buttons render always and DISABLE at the boundaries, presentation only — the host page owns the state machine and passes hasPrevious/hasNext/limit/page/total, clicks re-dispatch as `sf-pager-prev`/`sf-pager-next` and a size change as `sf-limit-change` with the number; the row WRAPS and the ≤480px band keeps the accessible name while the value and caret stay visible); **`content-card`** is the ONE content card element (`<content-card>`): four shapes (`grid`, `hero`, `row` with `dense`, `detail`), typed inputs, and two action slots (`actions` in-flow, `overlay` for a linked row's corner control). Every content surface composes it, the input-by-shape contract is the element's doc comment, the geometry is `content-card.css`, and `architecture.test.ts` guards the surface list. `controls.css`/`controls.ts` and `forms.css`/`form-field.ts` are the control vocabulary and the form sheet — the mechanism rules (native-control constraint, shared-sheet import guard, zero-specificity base) live in `components.md`/`css.md`. `content-stats.css` renders the indicator chip; `events.ts` carries the cross-feature window-event contracts (`FAVORITE_CHANGED_EVENT`/`COMMENT_COUNT_CHANGED_EVENT`/`AVATAR_CHANGED_EVENT` — the two content events carry detail interfaces, the avatar event is detail-free — plus the `ContentKind` union). Feature-specific UI stays in its feature.
- `catalog/` holds the `el` groups the shell, the features, and the shared primitives resolve. The anglicism policy and the `lang="en"` scope rule live in the pattern docs.
- `config/` holds community link constants (`links.ts`) and `vapid.ts` — the public VAPID key, pinned equal to the Go config default, `.env.example`, and the compose fallback by backend pin tests; the private half never touches the frontend.
- `pwa/` holds the install affordance: `install-prompt.ts` (the module-scope stash of the deferred `beforeinstallprompt` event, its subscriber set, the `appinstalled` clear, and the per-browser `notificationsGranted` predicate — wired once by `core/index.ts`; `resetInstallPrompt` is tests-only) and the `install-control` element. Read the lifecycle comment in `install-prompt.ts` before touching the stash — the event can fire before either host renders, and `prompt()` is single-use.
- `utils/` holds pure shared logic: `format.ts` (the date formatters, `initialOf`, the failure→catalog `mapError`), `url-cursor-paging.ts` (`UrlCursorPagingController` + `PAGE_SIZES`/`DEFAULT_PAGE_SIZE`), `platform.ts` (`isIOS` incl. the iPadOS desktop-mode heuristic, `isStandalone`), `roles.ts` (the client-side visibility predicates `isStaffRole`/`isSuperAdminRole`/`isContentCreatorRole` and the shared `roleLabel` map with the `roleUnknown` fallback), and `toggle-debouncer.ts` (`ToggleDebouncer` + `TOGGLE_DEBOUNCE_DELAY_MS` = 300 — the delay constant and the test timer stub are coupled). Add here when a second pure helper appears; don't pre-create modules.

## Folder-local conventions

- **Icon-only action buttons.** Delete, edit, and update controls — and the same kind of per-item action button — use an icon instead of text. `ui/icons.ts` carries the Feather set: `trash` (delete), `key` (password reset), `edit` (the pencil — comments edit + every staff edit affordance), `x` (remove), `reply` (corner-up-left), `save`, `chevronDown`. A per-item icon-only control ALWAYS names itself: `aria-label` (catalog wording) + `title` with the SAME string — an `<svg>` carries no accessible name, and a `title` is the only hover affordance an icon has — and it keeps a ≥2rem target box (WCAG 2.5.8) with the glyph centered. The header, pager, and toggle icons rely on the accessible name alone (`components.md` rule 11). Where the action has a pending state, the label swaps to the pending catalog key while the request is out (the glyph cannot spell "in flight"): `comments.deletePending` / `notifications.deleteOnePending` / the member panel's `resetPending`+`deletePending`. Form controls keep their TEXT (a submit/cancel inside a composer or a save button with a visible label), and so does a page-level toolbar verb — only per-item row actions are icon-only.
- The catalog (`catalog/el.ts`) is the single source for Greek copy. `el.test.ts` enumerates the existing groups — new keys in them are auto-pinned; a NEW group needs its own enumeration call.
- Deliberate anglicisms keep their English copy AND get two things: a catalog comment naming the owner ruling that settled the wording, and a `lang="en"` scope at the render site so assistive tech pronounces them correctly. A WHOLE-VALUE label takes the scope; a Latin loanword inside a Greek sentence renders plain, because Greek speech with a loanword is the intent. Structural and decorative glyphs are exempt from the catalog.
- Unknown problem types and violation codes must fall back to `el.ui.error` with a console.warn — raw machine paths/codes never reach the UI.
- `parseRetryAfter` is whole-integer-seconds ≥ 1 only (the OpenAPI `RateLimited` contract); an HTTP-date or junk is deliberately dropped — do not "fix" it to parse dates.
- The 401 auto-transition (clear CSRF token + registered callback) is the default for every endpoint; only `changePassword` opts out (`suppress401Callback`). New endpoints inherit the default — opt out only for a contract reason.
- `types.ts` holds only the transport-level problem shapes (RFC 9457 + violations). Feature request/response DTOs live in each feature's `data-access/types.ts` and mirror the Go handlers there — update both sides together.
- `request<T>`'s `as T` casts are runtime-unsafe by accepted tradeoff (thin wrapper over codegen) — integration tests are the safety net; do not add a codegen dependency silently.
- `request`'s `onResponse` option fires ONLY after a successful parse, never on failures — it is the single mechanism for header inspection (the comments create/reply `Location` is the only consumer today).

## Gotchas

- `api/test-utils.ts` is the only place that touches the happy-dom `happyDOM` namespace. Suites that must capture raw history calls patch `window.history` directly and restore the descriptors in afterEach — the shared shim routes URLs through `happyDOM.setURL` but does not record calls. Tests must pair `shimHistoryLocationSync` with `restoreHistoryLocationSync()` and `setHappyDOMURL` with `resetHappyDOMURL()` in `afterEach`; never cast to `window.happyDOM` directly in a test file. `stubProperty(target, name, value)` owns the prototype-shadowing stub for window/navigator globals and restores by DELETE when the field did not exist — assign-and-restore leaves an own `undefined` property that still satisfies `"x" in globalThis`; `waitFor(condition)` polls async handlers that outlive `updateComplete`. Fetch doubles in shared suites route through `mockFetchOnce`/`mockFetchImpl` and restore with `restoreMockFetch()`; the history and debounce stubs refuse a second install until their restore runs.
- Test files read their fixtures (CSS contract pins, `public/` artifacts, entry-point source) with the BUN API — `await Bun.file(new URL(…, import.meta.url)).text()` / `.arrayBuffer()`. Do not import `node:fs` (one runtime, no mixing); a module-scope read uses top-level `await`, and an in-test read makes that `test(...)` async.
