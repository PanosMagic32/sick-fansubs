# AGENTS.md — Comments Feature

The inline comments thread on blog posts and projects: sort tabs (top/newest/oldest, `?sort=` in the URL), hearts with the materialized counter, one reply level, author-only edits, author/moderator+ hard delete with a confirm, the `focus=` deep-link contract (`#comment-<id>`), and the unified notification feed (`user_notifications`); the `comment`, `comment_reply`, `heart`, and `comment_removed` kinds render in the notifications feature.

## Open this file when

- changing the comments wire calls, the thread element, the deep-link flow, or the catalog copy (`el.comments` group lives in `shared/catalog/el.ts`).
- changing the unified feed's `comment_reply` half (rendering lives in `features/notifications/`; the wire types in its `data-access/`).

## Placement

- `data-access/types.ts` mirrors the Go handler DTOs (`internal/handler/comments.go`: commentAuthorDTO/commentDTO/commentCountResponse — the list envelope is the shared `collection[T]` in `internal/handler/collection.go`) — update both sides together (shared AGENTS convention). Top-level items also carry `replyCount` (total) and `repliesEndCursor` (opaque continuation, absent when the window is complete), and `replies` is the inline WINDOW of 3 — not every reply.
- `data-access/comments-api.ts` owns the nine endpoint functions on the shared transport: the three public GETs (list, count, replies) and the six CSRF writes (create, reply, PATCH update, DELETE, and the PUT/DELETE heart pair). Create/reply return NO body — the 201 `Location` (`?focus=<new id>`) is the deep-link resource; `focusFromLocation` parses it via the transport's `onResponse` hook (the only header-inspection need in the app).
- `ui/comments-thread.ts` is THE thread element — `<comments-thread kind="blog-posts"|projects" content-id="…">`. **Sections:** the element keeps the list state, URL sync (`?sort=`), deep-link scroll/focus, and `render()`; the composers (top-level, reply, edit) live in `ui/comment-composers-section.ts` and the per-comment rendering plus hearts/deletes/reply-window appends in `ui/comment-items-section.ts` as reactive section controllers the thread renders through their template methods — one shadow root, same DOM.
- `ui/comments-section.ts` is the click-to-load wrapper the detail pages embed (`<comments-section kind content-id .count>`), NOT the thread: collapsed it renders the indicator from the detail item's `commentCount` plus the CTA, and it mounts the thread on a click or a `#comment-<id>` fragment. Both detail pages embed the section (the recorded cross-feature edge, components.md rule 2); never re-embed the thread directly.

## Folder-local conventions

- **Click-to-load.** The section issues NO request while collapsed — the count comes from the detail item, so the first `/comments` read is the expanding click. It expands itself when the URL carries `#comment-<id>` on load and on any later URL change that adds one (popstate, `NAVIGATE_EVENT`); a deep link that landed collapsed would break the notification jump. A CTA expansion (never a deep-link arrival) then scrolls under the sticky header via `scroll-margin-top` and moves focus to the inner labeled `<section class="cs" tabindex="-1">` (NOT the host — a host focus would announce nothing) because the button it replaced is gone — keep both if you touch `_reveal`. `scrollIntoView` is guarded (happy-dom lacks it, the thread's focus scroll precedent).

- **XSS defense**: comment bodies are text-only Lit bindings (never `innerHTML`); the server rejects control characters and the body renders with `white-space: pre-line`. Bodies go through `commentBodyTemplate` (emoticons.ts), which composes Lit templates over the same plain segments — do not add markup rendering, and never feed a body to `innerHTML`.
- **Emoticons**: `ui/emoticons.ts` owns the token table, the tokenizer, and the colored glyphs. Ruled tokens only (`:)` `=)` `:D` `:(` `;)` `:P` `<3` `:O` `:/`; the colon-style ones also accept their `-` nose form — `:-)` `:-D` `:-(` `;-)` `:-P` `:-O` `:-/` — and `=)` accepts `=-)`; `<3` has no nose form), matched case-insensitively and longest-first, skipped inside URL-looking runs. The `EMOTICONS` table is the ONE source for tokens, labels and glyphs, so add a token there (and to the test's token list) and nowhere else. The stored body is never rewritten — the glyph presents the token, so a selected body copies the glyph (empty text), not the ASCII token. Two gotchas the code documents and the tests pin: SVG fragments MUST use Lit's `svg` tag (a fragment rooted at `<circle />` in a plain `html` template is HTML-parsed, the self-closing slash is dropped, and the second eye nests inside the first), and a glyph's children leave a whitespace text node inside the `<svg>` (SVG renders nothing for it; it only leaks into `textContent` and copies, which is why the render test normalizes whitespace). Glyph colors are asset values (the classic emoji yellow/brown/red), not theme tokens; each glyph is `role="img"` with a catalog label (`el.comments.emoticon*`) — meaningful, so never `aria-hidden`. The heart reuses the exported `heartPath` from `shared/ui/icons.ts` so the geometry cannot diverge.
- **Deep links**: the `#comment-<id>` fragment becomes the list's `focus` param on load (and on popstate re-reads). Arrival scrolls center-block, smooth unless `prefers-reduced-motion`, with the target chip + one-shot highlight (`.is-target` flash). A focus whose target is absent (hard-deleted anchor → server returns page 1) shows the deleted-target notice at thread top. Create/reply reuse the same flow via `history.replaceState` — a jump must not spam history.
- **URL sync**: `?sort=` rides the URL (pushState on tab change, popstate re-read) — the search-page convention. Default `top` is omitted from the URL. Sort is a fieldset of visually-hidden radios styled as pills (the search type-filter pattern; keep the CHILD combinator in CSS).
- **Session gating**: list + count are public; the anonymous composer AND the inline reply composer render the sign-in prompt (link `/sign-in`); hearts render as plain counts (no button) for anonymous. The session comes from `sessionContext` via the cross-feature authenticated-capability exception.
- **Composer byline.** The signed-in composer opens with the same byline shape a comment carries — the avatar column beside a `.ct-meta` line whose `.ct-name` is the viewer — and the submit row (`.ct-composer-foot`) holds the action control alone, right-aligned. The name is user data, not catalog copy.
- **Hearts**: the confirmed-update machine — pending disables, success flips hearted + count locally, failure keeps state with a per-comment inline error. No optimistic flip. Heart states render as the shared SVG pair (`icons.heart`/`icons.heartFilled` — one path, one box) and the thread dispatches `COMMENT_COUNT_CHANGED_EVENT` from `@shared/events.js` after every successful count refetch so the detail-page indicator stays live. Own comments render NO heart element at all (self-hearts are forbidden — the server 422s `{commentId, invalidValue}`; DELETE stays 204), and every heart toggle rides the shared `ToggleDebouncer` (`@shared/utils/toggle-debouncer.js`, 300 ms trailing, per comment id — a click-play burst delivers at most one request, an even-click burst none; the button stays enabled during the window, `aria-busy` + the `.is-pending` dim, `disabled` only during the request phase).
- **Staff badge**: the text is always `el.comments.staffBadge` and stays `--sf-text` (AA in both themes); the **BORDER** color reads the author's derived `staffRole` (`ct-badge--moderator|admin|super-admin` over `--sf-accent-light`/`--sf-success`/`--sf-error` — borders must clear 3:1, small text would not: `--sf-success` is ~3.7:1 in the light theme), and the role ALSO joins the badge's text as a visually hidden suffix (`«Ομάδα»: Συντονιστής` — visible text first, the label-in-name rule) plus the `title`. Do NOT go back to an `aria-label`: a plain `<span>` is role `generic`, which cannot be named, so it would announce nothing. Role copy comes from the SHARED `roleLabel` (`shared/utils/roles.ts`, incl. the `roleUnknown` fallback) — never a second local map. A non-staff author carries no `staffRole`; when one is missing the badge keeps the neutral base style.
- **Delete**: author or moderator+ (`isStaffRole`), `window.confirm` first (hard cascade removes replies). Staff-deleting-others emits the server audit event AND the actorless `comment_removed` feed/push notice to that comment's author — the client sends nothing extra and renders the notice on `/notifications`.
- **Icon-only action row.** Reply, edit and delete render as the shared glyphs (`icons.reply` / `icons.edit` / `icons.trash`) instead of text: the row keeps its width on a phone. Each button carries `aria-label` + `title` from the catalog (`el.comments.reply|edit|delete`) and a ≥2rem box (`.ct-action`, glyph 1.05rem — the heart's count keeps its 0.8rem); the delete swaps to `el.comments.deletePending` and disables while the request is out. Tests identify the buttons by `aria-label`, never by text: the row's textContent must stay EMPTY (the stray-literal pin).
- **Edited marker**: `updatedAt > createdAt` (string compare on the fixed-width canonical timestamps — the blog/projects meta policy).
- **Load-more**: keyset pages of 20 top-level comments APPEND (not URL paging — the thread is not a routed list); the button renders only on `hasNextPage`. `focus` and `after` are never sent together (server 400). **Reply window:** each top-level item shows at most 3 replies; when the item carries `repliesEndCursor` a `.ct-more-replies` button appends the next reply page IN PLACE via `listReplies` (`REPLY_PAGE_SIZE`, the item's cursor as `after`) — the server's cursor, never a locally built one. The label shows `replyCount` in parentheses (decremented locally when an inline reply is deleted); a null `endCursor` hides the button. Each append owns an `AbortController` in `_replyAborts` and passes `requestSignal`, and `_loadFirst` aborts them ALL: a stale page must never append onto a fresh window (duplicates + a regressed cursor). `_appendReplies` also compare-and-swaps on the cursor it was issued with. The mid-window focus case (the server returns a reply page that is not the first) can leave earlier replies unreachable — accepted (the same class as an out-of-range top-level focus page).
- The thread aborts its in-flight list request on teardown/supersede and uses `requestSignal` for the 15s client timeout (page convention). The count is best-effort — failures just drop the number from the title.
- The detail pages' test stubs no longer intercept `/comments` URLs — the section issues no request until a click, so a stray comments read in those suites is a real bug, not noise (the detail-request assertions pin it).
- **Debounce tests**: the thread test file uses the shared `stubDebounceTimers` helper (`@shared/api/test-utils.js`) — it captures `window.setTimeout`/`clearTimeout` calls with the debounce delay and expires windows with `timers.fireAll()`; a click without a fireAll sends nothing (installed in `beforeEach`, restored in `afterEach` — the shared happy-dom window leaks otherwise).
