# web/src/features/search — Agent Navigation

Public search page: submit-driven merged search with a type filter, URL-synced query + cursor state, and a clear (×) button.

## Open this file when

- changing the search page behavior, the type filter, URL sync (popstate/NAVIGATE_EVENT), or the search wire types.

## Folder-local conventions

- **The URL is the single source of truth**: the paging controller's `onLoad` callback is the only entry that reads `location.search` into state and triggers loads. Every submit/type-change/sort-change/date-change/clear/popstate/NAVIGATE_EVENT flows through it — never set `q`/`type`/`sort`/`from`/`to` state elsewhere.
- **Pagination is URL-carried cursor paging:** the current page's `after` cursor, the page `limit`, and the 1-based `page` ordinal ride the URL; Next pushes `?limit=…&after=<endCursor>&page=<n>` (stamping the next ordinal; a size change drops it), Previous is `history.back()` (the prior cursor lives in our history entry). Previous is enabled only when the shared controller's `hasPrevious` is true — it derives from the CURRENT history entry's `sfPager` state marker, stamped by Next. Session-history state survives a refresh, so Previous stays usable after reloading page N; a shared/deep-linked page-N URL has no marker, so Previous renders DISABLED (back() could leave the app). It must NOT derive from the URL itself. Results are REPLACED per page, never appended — do not reintroduce load-more. The state machine lives in `shared/utils/url-cursor-paging.ts` (`UrlCursorPagingController` + `PAGE_SIZES`/`DEFAULT_PAGE_SIZE`); the pager UI is the `shared/ui/pager-nav` element: the controller's `hasPrevious` + the page's `hasNextPage` feed `?hasPrevious`/`?hasNext`, `@sf-pager-prev`/`@sf-pager-next` map to `paging.prev()`/`paging.next(endCursor)`, and the size select (`el.ui.pageSizeLabel`, options `PAGE_SIZES`) dispatches `@sf-limit-change` → `paging.setLimit(n)` — a size change is ALWAYS a restart at the first page (a cursor is only meaningful with the same limit). The caption BELOW the control row states «Σελίδα X από Y» from the URL's ordinal and `pageInfo.total` (Y floors at 1); the buttons stay visible and DISABLE at the boundaries (stable chip geometry); the pager is hidden on idle/loading/error/empty.
- **Refinements are never discarded:** the type filter, the sort select, and the two date bounds write the URL as soon as they change — INCLUDING while the page is idle, where they keep the user's pick (only a non-empty `q` triggers a request; an empty q is omitted from the URL rather than sent as `q=`; a URL `q` beyond the wire's 100-rune bound is ignored, so a long shared link cannot land on a guaranteed 422). The two date inputs listen to `input` AND `change` (browsers differ on which one a native date picker fires) and `_onDateChange` is IDEMPOTENT — an accepted pick's pair issues exactly ONE request, and a rejected pick issues none. The handler validates through the same canonical reader as the URL, so a pick the reader rejects (a pre-1970 year) is cleared from the field and never rides the URL. The date fields carry no value binding: `updated()` applies the URL-sourced value only to an UNFOCUSED input that is stale, so a re-render can never overwrite a pick mid-edit.
- **Submit-driven** — live-as-you-type is out of scope. The page's form is the only search input; the submit button is the catalog label, and the input carries a clear (×) button (`el.search.clear`) that resets to the bare `/search` URL + idle state, dropping any idle-picked refinements with it. The × renders for a submitted query AND for a typed draft (the native WebKit cancel control stays suppressed so URL/state always sync), and a click returns focus to the query input, whose own button the re-render removes.
- **Sort + date window:** a `<select name="sort">` beside the type filter — `date` (default, «Νεότερα πρώτα»), `oldest` («Παλαιότερα πρώτα») or `title` («Αλφαβητικά (Α–Ω)») — and two labelled `<input type="date">` fields (`el.search.dateFrom`/`dateTo`) for the inclusive publish-date window. All three ride the URL (`sort`, `from`, `to`), are read only in `onLoad`, and are part of every URL builder, so they survive Next/Previous/limit changes and popstate; changing any of them restarts at page 1 (`_buildURL` drops `after`/`limit`). A URL date that is not a canonical `YYYY-MM-DD` day is IGNORED by `readDateBound` (never sent — the server would 422 it). A refinement picked while the page is idle is KEPT in the URL and fetches nothing; the two date inputs are applied imperatively in `updated()` together with the sort select — happy-dom ignores the `selected` attribute (the pager-nav gotcha), and the imperative pass never touches a focused DATE input (the sort select, whose options are static, is always re-applied). Each sort's cursor is a DIFFERENT namespace (`sv1.` newest-first date, `so1.` oldest-first date, `st1.` title) and window-bound in documentation — never send a cursor across sorts or windows; the server answers 400 on a sort mismatch.
- `thumbnailUrl` is `string | null` (OpenAPI `[string, "null"]`) — the API never emits `""` for masked values, and the row passes `?? nothing` so the card receives the `null` (the card renders no image either way).
- The type badge copy: posts = Greek "Αναρτήσεις", projects = the **Projects anglicism inside `lang="en"`** (same policy as the nav). The row is a `<content-card shape="row">`: the badge text is the card's `badge` input (a template for the anglicised project label, a plain string for posts) and the visuals ride `badge-tone` — `accent` for posts, `project` (the muted red pair, distinct from `--sf-error`) for projects. The page also wires the card's `subtitle` input from the hit (the post's display line; empty for projects, where the card renders the plain title) — the row then reads «Title – Subtitle» inline, the same treatment as the blog grids. In the FILTER, `.type-option > span` is a CHILD combinator — a descendant selector would pill the nested `lang="en"` span (the chip-in-chip shape).
- Types mirror `internal/handler/search.go` + the OpenAPI `searchContent` operation — update together. The API result discriminator is the singular `"post" | "project"`; the filter values are the plural `"posts" | "projects"` — `_badgeLabel` and `_filterLabel` keep the two sets separate.
- The cursor is only meaningful with the same q+type+sort+window: `_load` must pass the CURRENT `this.q`/`this.type`/`this.sort`/`this.from`/`this.to` and the cursor the controller handed it, never cached values.
- `requestSignal`/timeout live in `shared/api/request-signal.ts` — the page owns cancellation, the shared 15s deadline guards hung requests.

- **Submit control:** the button names its own action via the search-owned catalog key `el.search.submit` («Υποβολή»), distinct from the NAV label `el.nav.search` that names the input. At ≤700px it leaves the input's line and becomes a full-width row directly under the query (`.search-row` wraps, `.submit` takes `flex: 1 0 100%`); desktop keeps it inline beside the input, and Enter still submits either way. The look is the shared `.button .button--primary` vocabulary. Pinned in `search-page.test.ts` (label + the CSS band).
