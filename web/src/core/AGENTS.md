# web/src/core — Agent Navigation

App bootstrap: element registration entry point, route table, global and in-shadow styles.

## Open this file when

- changing the route table or programmatic navigation helpers.
- changing the entry point or global/in-shadow styles.

## Placement

- Core owns app-frame concerns only: bootstrap, routing, chrome, global styles. Product behavior belongs in `features/`, never here.
- Core may import features only under the accepted exceptions (element registration in `index.ts`; the session-aware shell and header; test files may import the elements they exercise, like `baseline.test.ts`'s style enumeration).

## Folder-local conventions

- **`Routes`, never `Router`** — `@lit-labs/router`'s `Router` silently never registers its window listeners under Lit; navigation stays shell-owned. Do not swap back.
- `core/index.ts` imports `features/*` for side-effect element registration — an accepted core→features exception.
- Global `index.css` does not cross shadow roots: every component imports `core/styles/baseline.css`, its in-shadow mirror. `architecture.test.ts` fails a styled component that drops the import or omits it from the styles array; `baseline.test.ts` spot-checks the resolved sheets at runtime — happy-dom has no layout, so the pins are source-level. `bunfig.toml` maps `.css` to bun's text loader so `?inline` imports carry real CSS under bun test (Bun otherwise resolves them to empty objects), and the pin is the baseline's own top-level `.sr-only {` form — component sheets reuse the pattern only comma-joined (`.sr-only,`), so that exact form can only come from the baseline.
- Guard redirects use `redirect()` (replaceState), never `navigate()` — Back must not ping-pong through guarded routes.
- The 404 fallback's copy (including the "404" heading) comes from the catalog (`el.ui.notFoundTitle` + `el.ui.notFound`); `fallback` is exported for `router.test.ts` to pin that. Structural glyphs are exempt — but a text heading is not a glyph.
- Known deferred routing limits: trailing slashes (`/sign-in/`) 404 (no canonicalization), `goto(pathname)` drops search/hash, and old Safari/Firefox render blank (no URLPattern polyfill) — do not fix silently.
- PWA: `service-worker.ts` owns the registration guard — production-only (`import.meta.env.PROD`), `'serviceWorker' in navigator`, failure swallowed, hourly `reg.update()`; `index.ts` registers on `DOMContentLoaded`. Registration is single-call by construction: the entry point calls it once and the hourly interval is deliberately process-lifetime (a second call would double the timer — keep the single caller). Vite dev and bun tests never register (tests run without `import.meta.env.PROD` set). `pwa-artifacts.test.ts` pins the REAL `web/public` artifacts — manifest fields, icon PNG signatures, the `SF_VERSION = "dev"` placeholder, the real-source `content="dev"` app-version marker the Go server replaces, and the conservative update policy (no `self.skipWaiting`/`self.clients.claim`). The `sw.js` fetch-handler logic is deliberately NOT unit-tested (static hand-written file, no build plumbing; the VPS smoke in `deploy/bring-up.md` covers it).
- Web push: `sw.js` also carries the `push`/`notificationclick`/`pushsubscriptionchange` handlers. The worker CANNOT import the TS catalog — its Greek sentence templates duplicate the catalog strings and `push-artifacts.test.ts` pins them EQUAL. The payload keys (`contentId`, not `contentID`) are the worker's contract, pinned against the Go side by the backend's `TestPayloadJSONKeys`. The `pushsubscriptionchange` handler relays a window message (`sf-push-subscription-change`) to open pages — the page-side `push-settings` component owns the resubscribe. **Self-test:** `kind: "test"` has NEITHER content nor actor, so its two branches (sentence, deep link) must run BEFORE the `contentTitle`/`contentKind` guards — the notification's title is the site name and the click lands on `/account`; `push-artifacts.test.ts` scopes its order pin to the `sentenceFor` body (the deep-link branch carries the same condition earlier in the file — a bare `indexOf` pin would be vacuous).
- Install affordance: the shared `install-control` element (`@shared/pwa/`, with its `install-prompt` state module) has TWO sanctioned hosts — the home-only donation strip and the account page's notifications tab. The deferred-prompt stash lives at MODULE scope in `install-prompt.ts`, wired once by `core/index.ts` (`watchInstallPrompt`, idempotent — a second wiring would double-notify), because `beforeinstallprompt` can fire before either host renders; clicking replays the event once (single-use, so `consumeInstallPrompt` clears the stash before `prompt()`). The control shows the button when the browser offers a prompt, the manual share-menu hint on iOS (`beforeinstallprompt` never fires there), and nothing when the app is installed (`isStandalone`) or when THIS browser already allows notifications (`Notification.permission === "granted"` — a per-DEVICE signal; a server-side "has push" flag would hide the control on a desktop because a phone is subscribed). `index.test.ts` pins the entry-point wiring with a SOURCE-LEVEL read as well as the behavioural case: every pwa suite in the worker calls `watchInstallPrompt` behind the `wired` guard, so the behavioural pin alone would pass even with the call deleted from this entry point. The shell chrome element `core/shell/offline-banner` renders under the header on every route — see `core/shell/AGENTS.md` for its contract, and note that a shell-template edit must keep `shadowRoot.children` flat (an unclosed `<app-header` start tag breaks the parse).
