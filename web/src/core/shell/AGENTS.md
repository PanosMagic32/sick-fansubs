# web/src/core/shell — Agent Navigation

Application chrome: app-shell (owns SPA navigation), app-header, app-footer.

## Open this file when

- changing click interception, popstate handling, dropdown open/close behavior, header layout/breakpoints, or the footer.

## Placement

- Shell components stay here (app-shell, app-header, app-footer, donation-banner, offline-banner) — chrome, not product features. Cross-cutting UI primitives (spinner, banners) graduate to `shared/ui/`; the install affordance is a shared pwa primitive (`shared/pwa/install-control`), not shell chrome, even though a shell component hosts it. `offline-banner` is chrome: it is the connection strip the shell renders on every route, not a reusable banner.

## Folder-local conventions

- The shell owns SPA navigation — window click interception, popstate, and the `NAVIGATE_EVENT` listener all live here; `_onLinkClick` is the interception contract (pinned by `app-shell.test.ts`).
- SPA interception is for http(s) targets ONLY: any other scheme (mailto:, javascript:, magnet:, …) passes through natively — a magnet: link must open the torrent handler, never land in pushState (pinned by the magnet test in `app-shell.test.ts`).
- Route roots cap at 48rem (`main > *`); opt wide routes (blog list, detail pages, projects, search) into the 80rem cap with the `wide-route` class in `core/router.ts`. FULL-bleed routes (account, the admin surfaces, notifications)
  opt into `.full-route`: no cap at FHD and below, capped at 1872px only >1920px — PIXELS not rem (the 112.5% root font would mis-size a rem cap). Both rules live in `app-shell.css` next to the default, pinned by `app-shell.test.ts` CSS-contract reads. **`main > *` also carries `min-width: 0`** — a route root is a flex item, so without it its automatic minimum size is its content's min-content width and one unshrinkable row widens the whole page (`css.md` rule 9, the shell shrink guard). `main` is TOP-aligned and only `.center-route` (the five auth routes + the 404 fallback) centers itself; the shared `.state-block` (`core/styles/baseline.css`) reserves the loading/empty/error footprint on every content list — an error or empty state is always inside one when the route above it has chrome.
- `/blog/*` titles: the shell maps the one-segment `/blog/:id` and `/projects/:id` detail shapes to `el.titles.blogDetail`/`el.titles.projectsDetail`; the detail page refines `document.title` with the content title after its fetch (the shell resets it on the next navigation).
- Interception resolves the raw href attribute against the document base and classifies the RESULT: a non-http(s) protocol passes through natively (scheme case-insensitivity comes from the URL parser), and a cross-origin target — including a protocol-relative `//host/…` — stays native. Do not go back to raw scheme-prefix matching. A link that resolves to the CURRENT pathname stays native (a reload), so a self-link never re-renders.
- Header breakpoints: full desktop >1300px; icon-only band 700.01–1300px (labels clip, never display:none; external arrow hidden); mobile dropdown ≤700px; ULTRawide >1920px (bigger than FHD — the right-side account/bell labels are REVEALED by un-clipping, the same mechanism in reverse). The band/mobile query strings AND the reserved pill geometry (padding+border-radius on the BASE nav-link rule; active state swaps colors only — the no-jump fix) are pinned by tests that read `app-header.css` from disk — a CSS edit must update the test. **Mobile dropdown chrome:** at ≤700px the open menu is a FLOATING panel — an OPAQUE `--sf-bg` fill (never a translucent `--sf-surface` + blur — it lets the page show through under the menu), a full 1px `--sf-text-dim` border (the 0.16-alpha `--sf-border` outline is not distinctive enough), a 16px radius, and a shadow — all pinned in the same CSS-reading test, which also fails if the panel regains a translucent token or a `backdrop-filter`. Never reuse the PAGE background with a single bottom border: against the dot grid the panel's edges vanish and the menu reads as content merely overlapping content. Clicks INSIDE the bar (brand, theme toggle, bell, padding) close it through a listener on the shadow root — at document level every inner target retargets to the host, so "inside the panel" cannot be decided there.
- Header layout: brand LEFT, nav CENTER (`.header-center`), account/theme/hamburger right. The header carries NO search box — the `/search` page owns the only search input (with its clear × button). `splitPath` stays for `_onNavigate` (query-string navigation is the search-page contract; the routes controller matches pathnames only).
- Nav order contract: projects → search → about (the LAST internal link) → `.nav-divider` (aria-hidden) → external Tracker → for staff: a SECOND divider → the Διαχείριση management link with the sliders glyph (a discreet, separate control AFTER the external link). The divider is vertical on desktop/band, horizontal in the dropdown — pinned by the two nav-order tests (anonymous + staff). **The account is NOT a nav entry:** the header's account chip is the ONE account destination at every width. The ≤700px dropdown carries no account row, and the stylesheet carries neither a `.mobile-only` class nor the `:not(.mobile-only)` escape hatches (base alignment rule + band rule); two tests pin the absence (no account link in `nav`, no `.mobile-only` in the stylesheet).
- Offline strip: `offline-banner` sits directly under `<app-header>` in the shell on EVERY route; it reads `navigator.onLine` on connect and follows the window `online`/`offline` events, which are wake-up calls only — the state always comes from the property (pinned). The host carries `hidden` while online, so the strip takes no space and stays out of the accessibility tree; no dismiss control, and no service-worker state is consulted (the worker is production-only). Copy is `el.offline.message` and never promises that cached pages load.
- Donation surfaces: `donation-banner` renders in the shell ONLY on `/` (gated on `currentPath`); the footer carries the support line on every page. Both link to `shared/config/links.ts` values with `target=_blank rel=noopener noreferrer`. The strip ALSO hosts `@shared/pwa/install-control` on its right edge: donation sentence + donation link as one left group, install control right — and because the control sets `hidden` on itself when it renders nothing, the row falls back to its CENTERED single-item layout (`.banner install-control { margin-left: auto }` against `justify-content: center`, pinned by the CSS-contract read in `donation-banner.test.ts`).
- Footer layout: three zones (status LEFT, support CENTER, ©+version RIGHT) in a host flex row with space-between; at ≤700px only the INNER zones flip to columns (support: text → divider → link; right: © over version) — never the host. The pill→edge-to-edge switch stays at the footer's own 640px. Pinned by app-footer.test.ts CSS-contract reads.
- The footer test pins the live-region span identity by reference across the async health flip — keep the same element across re-renders, don't rebuild it.
- Footer status labels Online/Offline are deliberate anglicisms (catalog comment) — render them inside `lang="en"`; the Greek loading state stays outside that scope. The status reads `/health/ready`, so Online means the application can serve (database, schema, and no restore in progress), not merely that the process runs (pinned by app-footer.test.ts). The probe is the recorded exception to the shared transport: it calls `/health/ready` directly — not an `/api/v1` endpoint, so no problem parsing, CSRF, 401 transition, or shared deadline applies — and carries its own short timeout (a failed or timed-out probe reads offline; pinned by app-footer.test.ts).
- The mobile dropdown closes on Escape AND on outside clicks (document-level listener, `composedPath()` decides inside vs outside) — focus containment stays deferred.
- Account menu: signed out, the account chip is the plain `/sign-in` link; signed in, the chip (avatar + clipped username) is a disclosure button (`aria-expanded` alone — the panel is conditionally rendered, so an `aria-controls` would dangle while closed, and `aria-haspopup` would promise a menu that never opens; no roving tabindex) opening the account panel: «Λογαριασμός» → `/account` (aria-current on the current route), «Αποσύνδεση», and «Αποσύνδεση από όλες τις συσκευές». The sign-out buttons call the session context and disable while in flight; a failure shows the mapped message inside the panel (`role="alert"`) and a 403 revalidates (the account page's stale-CSRF heal); success closes the panel — a protected route's guard redirects, a public page stays put. The panel is right-anchored under the chip and closes on Escape (focus returns to the chip), on an outside click, on a click anywhere else in the header (the shadow-root listener shared with the mobile dropdown), and on every navigation. It reuses the mobile dropdown's opaque chrome at every width. The panel's entries are button-faced rows and the current-route entry stays visually neutral — `aria-current` is semantic only there. The ≤700px nav dropdown gives its links the same button frame. The BRAND stays the plain home link in both states.
- Account link + bell: the right-side account link is icon-only below the ultrawide tier — avatar image (fetched from the profile endpoint once per authentication) or the initial-letter chip, default user icon when anonymous; the label is clipped at the BASE rule (never display:none), so the accessible name is unchanged — and the clip selector is deliberately element-agnostic (`.header-right .link-text`), because the signed-in chip is a BUTTON, so an `a`-qualified rule would exempt it. ALL header icons share ONE 1.5rem size (the `a svg` rule; the theme toggle joins via its own rule); the account link's footprint and the theme toggle are BOTH 40px circles, the chip's letter at 1.5rem and the anonymous glyph 1.5rem centered in the same 40px box — one footprint across auth states. The bell renders for EVERY authenticated session (the admin-link predicate gates only the Διαχείριση link), lands on `/notifications`, and refreshes its unread badge on session changes, `currentPath` changes, and the page's `sf-notifications-changed` window event — never a timer; badge/profile fetch failures are deliberately silent (best-effort freshness). The bell's badge is pinned to the GLYPH via the `.bell-icon` wrapper — never onto the revealed label. Above 1920px both right-side labels are revealed (the un-clip query). `NOTIFICATIONS_CHANGED_EVENT` is exported from the notifications page and imported here. The avatar chip ALSO refreshes on the `sf-avatar-changed` window event (`AVATAR_CHANGED_EVENT` from `@shared/events.js`, dispatched by the account page after a confirmed upload — the avatar is not part of the session projection, so no session change announces it).

## Gotchas

- The shell's shadow DOM is pinned FLAT and ORDERED on a non-home route (`app-shell.test.ts`): a broken start tag in the render template parses the rest of the template as children of `<app-header>` (no slot), so the strip, main and the footer disappear while every route test still passes — the whole page reads blank. Assert `shadowRoot.children` (not a name lookup anywhere in the tree) and keep `<app-header>` childless when editing the template.
- Tests must not rely on happy-dom's default anchor navigation: `test-setup.ts` disables main-frame navigation and the `setURL` fallback, so an unprevented click neither fetches nor mutates the shared window URL. Assert navigation through the history shim instead.
- History restores are DELETE-based: `restoreHistoryLocationSync` removes the own property so the pristine prototype method shows through — a redefinition leaves a non-writable own property that breaks app-shell's assign-based history restore. Use the test-utils pair, never a local shim (local shims leak across bun's shared happy-dom window on CI).
- `_onLinkClick` reads the RAW href attribute — tests for raw-relative/hash hrefs must use `setAttribute("href", …)`: assigning `.href` serializes to an absolute URL and silently exercises the wrong branch (escaped locally; failed only on CI).
- The cross-origin interception test pins `origin` via `setHappyDOMURL` — ambient `location` reads in `_onPopState`/SPA tests are convention-protected (paired set/reset), not structural.
